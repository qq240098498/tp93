# tp93 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则有完整的状态流转——**起草 → 已复核 → 启用 ⇄ 停用**，每次状态变化都留下记录，启用前有四项把关，历史命中看得出当时管事的是哪一版。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5093>

端口固定为 `5093`，如需临时改动可在启动前设置环境变量 `PORT`。

## 状态怎么流转

一条规则从建出来到参与扫描，按下面的链路走：

1. **起草**：新建保存后一律是起草，此时只把内容写清楚，不参与扫描；适用文件类型可以先不选
2. **提交复核**：写完先自己过一遍，点“提交复核”到已复核；已复核状态下改了内容会自动退回起草，重走一遍
3. **启用**：只允许从已复核（或停用后再次启用）进入，启用前四项把关必须全过；启用那一刻规则各字段拍成一个版本快照（v1、v2……），之后才参与扫描
4. **停用**：启用中的规则可以停用，停用后不再参与扫描，但历史批次里的命中全部保留；停用后改内容会升版前先退回起草，重新复核、重新把关后才能再启用，版本号递增

启用中的规则不能直接修改、也不能删除——要先停用。页面右上角必须填“当前操作者”，新建规则与每一次状态流转、扫描都要带上操作者。

## 启用前的四项把关

点“启用”时逐项检查，任何一项没过都不允许启用，并写清卡在哪一项上（弹层里逐项列出 ✓ / ✗）：

1. **匹配写法**：不能为空、不能超长
2. **适用文件类型**：起草时可以不选，但启用前必须选定（全部或具体类型）
3. **规则编码**：不能和清单里已有的规则编码撞上（保存时也会先拦一次）
4. **同类写法**：匹配写法一字不差、适用文件类型又有交集（`全部` 与任何类型都算有交集），且另一条规则正处于启用状态——需要先停用对方或改掉写法

也可以在点启用前先看把关结果：`GET /api/rules/:id/enable-checks` 只检查、不改状态。

## 每次状态变化留记录

规则上挂着流转记录（`transitions`）与启用版本快照（`versions`）：

- 每条记录写明**动作、从什么状态到什么状态、什么时候、由谁做的、说明**；说明可以不填，页面上会显示“未写说明”
- “新建”“提交复核”“启用”“停用”“退回起草”都各有一条
- 每启用一次生成一版快照，记版本号、当时的编码/名称/级别/适用类型/匹配写法/说明、启用时间与启用者
- 页面上每条规则点“流转记录”可以看到完整时间线与各版内容

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、版本、适用文件类型与匹配写法，可按级别、状态、类型筛选与关键词搜索；操作列按当前状态给出能走的动作（提交复核 / 启用 / 停用 / 修订 / 流转记录 / 删除）
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面
3. 命中清单区可选定只看某一条规则、某一个文件或某个级别，点按规则扫一遍，给出参与规则数、文件数、命中数，并按级别、规则、文件汇总；每条命中标着当时的规则版本号
4. 扫描批次历史区列出每一轮扫描（时刻、操作者、范围、参与规则数、命中数），点“查看详情”能看到当时参与比对的规则版本快照与全部命中，并对照规则现状标出**停用、已改版（从第几版改到第几版）或已删除**
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应输入项上；启用把关失败时四项结果直接摊在弹层里

## 比对口径

- 只有状态为启用的规则参与比对；指定一条非启用规则扫描时，页面上写明这一轮它没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条
- 每轮扫描存为一个批次，命中与参与规则的字段连同版本号一起快照进批次；规则后来停用、改版甚至删除，都不影响历史批次的内容

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有四种：起草、已复核、启用、停用，状态只能走动作接口流转，不能在编辑时直接指定
- 匹配写法不能为空，最长 60 个字符
- 适用文件类型起草阶段可以先不选，启用前必须选定
- 操作者名字必填，最长 40 个字符；流转说明最长 200 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...], "scanBatches": [...] }`。规则含状态、版本号、版本快照数组与流转记录数组。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件；文件缺失或内容损坏时会自动回落到初始数据。旧版本数据（只有启用/停用两个状态、没有流转记录）载入时会自动补录来历与版本快照，历史数据不用手动改。

## 接口一览

| 方法   | 路径                          | 说明                                             |
| ------ | ----------------------------- | ------------------------------------------------ |
| GET    | /api/health                   | 服务状态检查                                     |
| GET    | /api/rules                    | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules                    | 新建规则（一律起草，需带 operator）              |
| GET    | /api/rules/:id                | 查看单条规则（含流转记录与版本快照）             |
| PATCH  | /api/rules/:id                | 修改规则内容（启用中被锁；已复核/停用改内容退回起草） |
| DELETE | /api/rules/:id                | 删除规则（启用中需先停用）                       |
| GET    | /api/rules/:id/enable-checks  | 只看启用把关的四项结果，不改状态                 |
| POST   | /api/rules/:id/review         | 提交复核：起草 → 已复核                          |
| POST   | /api/rules/:id/enable         | 启用：已复核/停用 → 启用，过四项把关并生成版本   |
| POST   | /api/rules/:id/disable        | 停用：启用 → 停用                                |
| GET    | /api/files                    | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files                    | 收录文件                                         |
| GET    | /api/files/:id                | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id                | 修改文件                                         |
| DELETE | /api/files/:id                | 把文件移出清单                                   |
| POST   | /api/scan                     | 按启用的规则扫一遍，存为批次并返回命中与汇总     |
| GET    | /api/scan-batches             | 扫描批次列表（概要，新的在前）                   |
| GET    | /api/scan-batches/:id         | 批次详情，命中对照规则现状标注停用/改版/删除     |

状态流转与扫描的请求体都要带 `operator`，流转动作可带 `note`。接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "...", "details": ... } }`，其中 `field` 用于让页面把问题标到具体输入项上；启用把关失败时 `details.checks` 是四项检查的逐项结果。
